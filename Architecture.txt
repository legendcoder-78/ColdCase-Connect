This is an incredibly strong and impactful hackathon problem statement. It tackles a massive real-world issue, identifies the specific bottleneck, and proposes a highly technical, multi-modal AI solution to solve it.

Here is a breakdown to help you fully internalize the core problem, visualize the product, and map out the specific technologies you will need to build it.

---

### **1. The Core Problem (The "Why")**

You are solving an **Information Silo** and **Human Bandwidth** problem.

* **The Status Quo:** When a detective in Bengaluru is looking at a cold case, a nearly identical crime might have happened 5 years ago in Delhi. Both cases are logged in the CCTNS (Crime and Criminal Tracking Network & Systems), but CCTNS is essentially a giant filing cabinet.
* **The Limitation:** Currently, finding connections requires a detective to know exactly what keywords to search for, or to simply remember a past case. Human memory cannot cross-reference millions of files across 17,000 stations.
* **The Result:** Serial offenders go uncaught, and patterns go unnoticed, simply because the dots are buried in too much data.

### **2. What You Are Building (The "What")**

You are building an **AI-Powered Multi-Modal Search Engine** specifically tuned for forensic investigation. It is not just a search bar; it is an analytical tool.

Here is the user journey you are building:

1. **Input:** An investigator uploads a photo of a new crime scene and types out a quick summary of the case.
2. **Vectorization (The Magic):** Your system mathematically reads the image and the text, turning them into arrays of numbers (embeddings) that capture the *meaning* and *visual context*, not just keywords.
3. **Retrieval:** The system scans the historical database to find the mathematically "closest" cases.
4. **The Output Dashboard:** It presents the Top 5 matches. For each match, the investigator sees:
* A side-by-side comparison of the old case and new case.
* An AI summary explaining *why* they match (e.g., "Both scenes feature a specific knot tied on the victim's left hand and forced entry through a window").


5. **The Divergence Flag (The "Aha!" Feature):** This is the smartest part of your product. If the system finds a past case where the text description matches perfectly, but the visual evidence is completely different (or vice versa), it flags it. This suggests a suspect might be *trying* to copy a known M.O. (staged scene) but failing to get the visual details right.

### **3. The Tech Stack (The "How")**

To build this in a hackathon setting, you need a stack that is powerful but fast to implement. Here is the exact architecture you are looking at:

#### **A. The Embedding Models (The Brains)**

* **Visual Similarity:** **CLIP (Contrastive Language-Image Pre-training)** by OpenAI. CLIP is perfect because it was trained on text-image pairs, meaning it understands the semantic meaning of images.
* **Text Similarity:** **Sentence-BERT (SBERT)**. SBERT is a modification of the standard BERT network that derives semantically meaningful sentence embeddings. It is incredibly fast for comparing text similarity.

#### **B. The Database Layer (The Memory)**

* **Vector Database:** You cannot use a standard SQL database for this. You need a database built to store and search high-dimensional vectors (the numbers generated by CLIP and SBERT).
* *Recommended for Hackathons:* **Pinecone** (cloud-based, easiest to set up), **ChromaDB** (local, very easy for Python), or **Qdrant**.

#### **C. The Scoring & Logic (The Math)**

You will need to write a Python script that calculates the final scores.

* **Combined Score:** $S_{combined} = (w_1 \times S_{visual}) + (w_2 \times S_{text})$ *(where $w$ represents the weight you give to text vs. images).*
* **Divergence Delta:** $\Delta = |S_{visual} - S_{text}|$. If $\Delta$ crosses a certain threshold, you trigger the divergence flag.

#### **D. The AI Explanation Layer (The Analyst)**

* **LLM API:** To generate the plain-English explanation of shared patterns, you will pass the text of the two matched cases into an LLM prompt.
* *Recommended:* **Gemini API**, **OpenAI API (GPT-4o mini)**, or **Claude 3.5 Sonnet**.

#### **E. The Frontend / Backend (The App)**

* **Backend:** **FastAPI** (Python). It is blazing fast and handles machine learning models perfectly.
* **Frontend:** If you have a React/Next.js developer, use that. If your team is mostly Python/Data Science focused, use **Streamlit**. Streamlit allows you to build beautiful, functional dashboards for AI tools in hours, leaving you more time to perfect the AI logic.
